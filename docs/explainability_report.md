# Explainability Report

This report presents the advanced diagnostic analysis for the Logistic Regression,
Neural Network, Random Forest, and XGBoost models. All analyses were performed on
the frozen test set using the locked model artifacts and the validation-selected
thresholds handed off by Sharwin. Quantitative results are drawn from the output
CSVs generated by `11_shap_analysis.py` and `12_explainability.py`

**Note:** SHAP/importance results describe model behavior, not causation.

## Answers to the Four Questions

**1. Why is the model making these predictions?**
All four models lean most on destination-byte/load features (`dbytes`, `dload`, `dmean`) and the connection-count feature (`ct_dst_sport_ltm`). SHAP (RF/XGBoost) adds `ackdat`, `ct_srv_dst`/`ct_srv_src`, `tcprtt`, `smean` as top drivers. Often, one or two features dominate a single prediction rather than a diffuse blend. The NN leans unusually hard on `swin`/`sload`, while LR leans on categorical encodings (`state`, `proto`).

**2. Can its probabilities be trusted?**
Reasonably at the extremes, but less in the 0.5–0.9 range for all four models. XGBoost has the 2nd-best Brier score but the single worst calibration gap (~0.47).

**3. Is it relying on unstable or dataset-specific features?**
Yes. 67% of features (26/39) show substantial drift (PSI > 0.2) between train and test. Every model has at least 3 of its top-10 importance features in the top-10 drift list (Random Forest worst, 7/10). The single highest-drift feature, `ct_dst_sport_ltm` (PSI 0.59), is also a top-5 importance feature for 3 of 4 models. The TTL ablation reinforces this. By adding `sttl`, TTL ablation gives a small accuracy bump (+0.0018 PR-AUC), but completely reshuffles feature rankings — a sign of a shortcut feature.

**4. Why does it fail on certain samples?**
Missed attacks (false negatives) look artificially "normal" — window-size, load, and timing features sit close to normal-traffic values. False alarms (false positives) are normal connections whose `response_body_len`/`sload` happen to resemble attacks. This pattern shows up independently in LR and NN, and RF/XGBoost's SHAP explanations converge on the same features for the same error rows. The pattern illustrates a hard subpopulation rather than an issue with the models.

## Conclusion
1. Predictions are driven by destination-byte/load and connection-count features across all models (NN additionally leans on `swin`/`sload`; LR on categorical encodings).
2. FP/FN cases differ clearly from correctly classified cases on `response_body_len`, `sload`, and window/timing features. The same error pattern shows up independently in both LR and NN.
3. SHAP confirms the permutation-based rankings for tree models (`ackdat` #1 by both methods) and catches one interaction effect (`ct_srv_dst`, XGBoost's #2 SHAP feature but a bottom-of-list permutation feature) that permutation importance missed.
4. Calibration is acceptable in aggregate (Brier < 0.15 for all models) but all four are overconfident in the mid-probability range. XGBoost has the single worst gap, but not the Brier-score outlier (LR).
5. Distribution drift is the biggest reliability risk. Two-thirds of features drift and the most-drifted feature (`ct_dst_sport_ltm`) is also a top-importance feature for every model.
6. The TTL ablation confirms a shortcut-learning risk, supporting the team's existing decision to exclude TTL features from primary models.
